# Security policy

## Scope

This policy covers the contents of this repository: its documentation, catalogue data, scripts and GitHub Actions workflows.

Report the following privately, not in a public issue:

- Credentials, tokens or personal data committed by accident.
- A catalogue link that points to a malicious or compromised destination.
- A vulnerability in the validation scripts or workflows.

Never post credentials or exploit details in a public issue, pull request or discussion.

## How to report

Email [hello@seeitflow.com](mailto:hello@seeitflow.com) with the subject "Security report: system-design". Describe the issue and where you found it. Do not include exploit code, credentials or personal data in the first message; the maintainers will reply with how to share further detail. Do not use public issues for these reports.

GitHub private vulnerability reporting is intended as an additional channel. It has not been confirmed as enabled; do not rely on it until the **Security** tab of this repository offers **Report a vulnerability**.

Confidential community and conduct reports go to the same address, as described in the [Code of Conduct](CODE_OF_CONDUCT.md).

## Out of scope

Vulnerabilities in the SeeItFlow website or application are not handled in this repository. Use the [SeeItFlow contact page](https://seeitflow.com/contact) and do not post details publicly.
